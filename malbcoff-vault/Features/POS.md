# POS
`pages/pos.php` + `assets/js/pos.js` (cart in JS) → `actions/pos_search.php` (fetch JSON, no timeout/retry) → checkout is a **plain `form.submit()`** to `actions/complete_sale.php` (re-reads price/stock, inserts sales, sale_items, stock_movements in one transaction, then redirect + flash). `sale_no` from `generate_sale_reference()`.
**Weak-net risks:** no idempotency key → double-tap/retry can double-sell; fetch has no timeout; page reload loses cart state. Fix in Patch 6.
Roles: branch_manager, cashier only.
**Patch 6a (2026-10-17):** checkout is no longer `form.submit()`: `pos.js` → `SafeSubmit.run` (JSON, UUID key, 20 s timeout, Retry with same key, green "Saved" card until OK (English wording since Patch 7)). `complete_sale.php` returns JSON for `Accept: application/json` (classic redirect + flash path kept) and replays the first sale for a repeated key. Cart stays until success is confirmed.
**Patch 8 (2026-10-17):** prices are typed at checkout. Cart/search no longer show the placeholder price; **Checkout** → Set Prices sheet → Confirm Sale → (unchanged) cash check → confirm dialog → `SafeSubmit`. Server requires `price_mode` + `price` per line, computes everything in cents, saves `unit_price`, `line_total` (truth), `price_entry_mode`. "Last: ₱…" chip = this branch's last typed price (`actions/pos_last_prices.php`). Sold lines are final (DB trigger). See [[Patch 8 - Price at Checkout]].
**Patch 6c-2 (2026-10-17):** offline sales. If the network fails at Confirm, the sale is saved in the device outbox ("Sale saved on this device", temporary receipt `OFFLINE-<branch>-<date>-<n>`, **New Sale** without a reload) and sent later with the same key (`sales.client_id` UNIQUE); queued units show "In a queued sale" and cannot be added again; non-cash needs the cashier to tick "Payment received"; the server re-validates everything, a refused sale creates nothing and goes to the owner's Needs Action. See [[Patch 6c-2 - Offline Sales Outbox]].
**Patch 8B (2026-10-17):** checkout modal polish only. Set Prices input/line-total layout; after save the confirm dialog shows a compact "Sale saved" summary with one **New Sale** button (no green Saved card/OK; `SafeSubmit` `quietSuccess`). See [[Patch 8B - Checkout Modal Polish]].
