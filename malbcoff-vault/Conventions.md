# Conventions (sundin sa bawat patch)

- Server is source of truth; never trust browser price/stock/branch/role.
- Non-owner: branch = `Auth::branchId()` lagi. Owner: `current_branch_scope()` (`?branch=`).
- Mutations sa `actions/`, may CSRF (`_csrf`), transaction + `FOR UPDATE` + guarded `UPDATE ... WHERE status='available'` + check `rowCount()`.
- Every stock change → `stock_movements` row.
- State-changing submits from the UI go through `SafeSubmit.run()` (`assets/js/safe-submit.js`) with a client UUID; the action must support `Idempotency` (key + stored result inside the same transaction) — see [[Patch 6a - Weak Internet Safe Retry]].
- Prepared statements only. Native prepares: **bawal i-reuse ang same named placeholder** sa isang query (gumamit ng `:a1`, `:a2`).
- Escape output with `e()`.
- Schema change → ship a migration file `database/migrations/P3_0xx_name.sql` + runtime `SHOW COLUMNS` guard.
- New page = add to `$allowedPages` + `$pageRoles` in `index.php`, `app_url()` paths in `helpers.php`, sidebar + mobile-nav entries, and (production) `.htaccess` rewrite if clean URL is new.
- UI must match `DESIGN.md` + `design-reference/*.png` (cards, `kpi-card`, `data-table`, `filter-card`).
- **UI rules (Patch 7): English only, simple words, mobile-first 360/768/desktop, no horizontal page scroll, tap targets ≥44px, text ≥14px, tab + table pattern, zeros dimmed / values bold, KPI cards open the shared drawer, Saving... / Saved / Not saved yet... messages, owner and branch users share views.** Full rules + the **"Before finishing any patch" checklist**: `DESIGN.md` §15 (root of the project) — [[Patch 7 - English UI and Stock Monitoring Tabs]].
- Asset cache-busting is already `?v=filemtime`.
- **Sale prices (Patch 8):** a sale price only ever comes from the cashier's Set Prices entry (`price_mode` + `price` per cart line). Never use `products.selling_price` / `branch_product_prices` (placeholder) for a sale, never trust a browser total, store `line_total` as the truth + computed `unit_price`, and never UPDATE price/qty of a saved `sale_items` row (a DB trigger refuses it). See [[Patch 8 - Price at Checkout]].
- **Service worker (Patch 6b):** static files under `assets/` only — never cache PHP pages, `actions/*`, anything with login/session/CSRF, or a POST. Version = config `version` (APP_VERSION). New standalone pages include `partials/pwa-head.php` + `partials/pwa-register.php`. Emergency off: [[How to turn off the service worker]].
- **Offline outbox (Patch 6c-1, stock actions only):** to make a new state-changing action queueable, pass `outbox:{type,summary,lines,dedupe?,review}` to `SafeSubmit.run()` and add its endpoint to `ENDPOINTS` in `assets/js/outbox.js` (+ the type to `actions/outbox_report.php`). Rules: (1) the action must already honour the 6a `Idempotency` key — the outbox item id **is** that key; (2) store only what the normal form sends — never a password, `_csrf`, page nonce or token (the sender gets a fresh CSRF from `actions/outbox_status.php`); (3) the server re-validates everything with the current session — never trust the queued payload; (4) the device never changes a displayed stock/price number, pages show "N queued actions are not counted yet." instead; (5) network/5xx/`in_progress` = retry (5 s → 15 s → 60 s → 120 s), definite refusal (422/403/409) = **needs_action** (never retried, reported to the owner), 401/419 = pause + resume after login, never discard automatically; (6) items belong to one user + branch scope — another user never sees or sends them; (7) one sender per scope (Web Locks / lease), FIFO; (8) no IndexedDB = plain 6a Retry card; (9) sales were added later by Patch 6c-2 (rules below). See [[Patch 6c-1 - Offline Outbox for Stock Actions]].
- **Offline sales (Patch 6c-2):** a POS sale is queued with `outbox:{type:'sale',…}` on `SafeSubmit.run()` and sent to `actions/complete_sale.php` with `X-Outbox-Send: 1`. Rules: (1) the sale's idempotency key **is** its client id, stored in `sales.client_id` (UNIQUE) as a second guard — a duplicate or retry returns the existing sale as "already processed", never a second one; (2) the payload is what the checkout form sends (typed `price_mode` + `price` per line) plus `offline_device_time` and `offline_receipt_no` — never `_csrf`, a token or a password; (3) the server re-validates everything with the current session (branch = session, unit still `available` at that branch, stock, prices > 0, totals in cents) and ignores browser totals; a definite refusal (422/403/409) creates **no partial sale**, becomes **needs_action**, is never retried and is reported to the owner (`outbox_reports`, `action_type='sale'`, with items, amounts, payment, device time, reason); resolution is manual ("Mark as resolved" + note), no automatic force-sell; (4) the device time sets `sales.created_at` (and that sale's `sale_items` / `stock_movements` `created_at`) only for an outbox send, only when it is not in the future and not older than 7 days — so every report counts the sale on the same day — and both device time and server `received_at` are stored; (5) queued sales never change a shown stock or sales number: pages show "N queued sales are not counted yet."; (6) queued units / accessory quantities are **held on the device** (`Outbox.holds()`) and shown as "In a queued sale" — a hint only; (7) non-cash payments cannot be verified offline: the cashier must tick "Payment received" before the sale is saved; (8) warn, never block, at > 50 queued sales or a sale older than 24 h ("Please connect to the internet to send your sales."); (9) "New Sale" after a queued sale must **not reload** the page; (10) owner, System Admin and impersonation have no outbox. See [[Patch 6c-2 - Offline Sales Outbox]].
- **Login and auth pages never depend on enhancements, and are never cached (BUG Tablet Login):** `login.php`, `change-password.php`, `maintenance.php` (and logout, ping, session/CSRF helper endpoints) must work with no JavaScript, no service worker, no IndexedDB. They load only `sw-register.js` in `data-mode="auth"` (set `$pwaAuthPage = true` before `partials/pwa-register.php`), send `no-store`, and show a clear English reason when sign-in fails. The service worker must **never** intercept a page request, a POST, `actions/*` or anything with login/session/CSRF — a request re-sent by a worker has a different User-Agent and the UA-hash session check logs the user out. Change `sw.js` only inside the static-file branch. See [[BUG Tablet Login Stays on Login Page]].
- Keep patches small: 1 patch = 1 feature, listed files lang.

## Inventory lifecycle and zero-stock visibility — 2026-10-20
- Branch deletes are **soft deletes** (status deleted + actor/time/branch; optional reason). Only a direct, unimpersonated **System Admin** may permanently clean units. Server must enforce the role, CSRF, transaction, locks and idempotency.
- Every branch removal writes a -1 **Removed from inventory** movement in Other. Never delete ledger rows to erase stock or force eligibility. Do not count deleted/archived units as current stock or allow selling/transferring them.
- Permanent cleanup releases IMEI, IMEI 2 and serial only after admin confirmation. **Only units referenced by a sale item or any void stay archived** (save original identifiers, NULL live identifier fields; keep their history intact). Every removed unit with sales=0 AND voids=0 can be hard-deleted, including previously archived units, regardless of transfers/movements. Write the required audit snapshot first inside the transaction; detach transfer lines with product/identifier snapshots and keep parent transfer quantities/statuses. Convert movement rows to snapshots (NULL unit_id + deleted_unit_id + unit_snapshot), keeping quantities/dates/references so dated reports reconcile. Never weaken scanner duplicate checks; snapshots do not reserve identifiers. Delete all with no sales previews all branches/pages and requires exact typed DELETE plus a revalidated preview token. See FIX 8C-2 in [[BUG Deleted Inventory Units and Blocked Identifiers]].
- Previously stocked active catalog models **stay visible at zero** in branch/owner/matrix and exports. All / In stock / Out of stock default All. Never-stocked and removed catalog models stay absent. Keep the shared report, current catalog predicate, dashboard live drawer and totals consistent; preserve historical sales money.
- See [[BUG Deleted Inventory Units and Blocked Identifiers]], [[BUG Stock Monitoring Hides Zero Stock Models]] and [[Design System]]. FIX 8C-2: **done, not yet live**; everything preceding FIX 8C-2, including P3_006 and zero-stock visibility: **LIVE**, confirmed 2026-10-21.
